# Acceptance tests

Run the full retained workflow in a Windows 11 x64 VM:

1. Launch the matching executable, choose Run once, approve first-run deployment, and confirm Start with Windows is disabled with an install action. Relaunch, choose Install, verify `%LocalAppData%\Programs\StageSwap\StageSwap.exe` and both per-user shortcuts, then relaunch without elevation.
2. With the managed app hidden in the tray, launch it again and verify the existing dashboard is shown. Launch a different packaged build, reject replacement and verify nothing changes, then accept it and verify the old process exits gracefully, the new dashboard opens, settings remain intact, and the startup registry value names the stable managed path. Verify a non-responsive or legacy instance is never force-terminated and produces manual-exit guidance.
3. Simulate replacement startup failure and verify the previous executable is restored and relaunched. Verify `--cleanup` retains the managed executable and user data; verify `--uninstall` removes startup, camera deployment, the managed executable, and both shortcuts while retaining `%LocalAppData%\StageSwap` data.
4. Keep the installed DLL loaded in Windows Camera, launch a newer build, and verify deployment switches to its content-versioned DLL without an access-denied failure. Confirm the locked old copy is removed after reboot.
5. Confirm the mismatched package is rejected and cannot register its camera-source DLL.
6. Select the single expected webcam, relaunch, and verify that the saved device opens as fixed 720p30 RGB32 capture.
7. Select the current monitor, relaunch, and verify its friendly label restores the same display. Remove or rename that display and verify the first secondary display is selected, with the sole primary used on a single-monitor system.
8. Capture and import references, Rescan, and verify a new highest-scoring monitor is selected only after the immediate confirmation scan and becomes the persisted selection.
9. Exercise all four combinations of **Find reference display automatically** and **Recover black screen capture automatically**. When discovery is disabled, verify startup, Settings-open, 30-second, reference-capture, and reference-import scans do not run; verify explicit Rescan and its monitor-confirmation pass still work, then re-enable discovery and verify an immediate scan. When recovery is enabled, force the selected capture to return black and verify the first 30-second check records pending confirmation and the second restarts screen capture without starting the all-display scan worker. Verify a non-black or missing check, monitor change, restart, disabling, or re-enabling recovery clears pending confirmation and starts a fresh interval. Verify explicit Rescan never contributes a black-screen sample. Parse legacy schema-1 configurations with the old rescan setting both enabled and disabled and verify the new recovery setting inherits that choice; verify an explicitly saved new recovery value overrides inheritance.
10. Exercise Automatic switching both ways, Force Webcam, Force Screen, and reversal during the 500 ms fade.
11. Verify the versioned main-window title, shared window/tray icon, sectioned dashboard controls, branded Settings sidebar, contextual Settings previews, cursor option, startup preferences, 14-day logs, and all four manual restart actions. In Settings, verify the General primer and page-specific explanations are always visible; toggle each complex setting and confirm its current-result line updates immediately, including launch and close/exit dependencies. Check all four documented Match strictness labels at their boundaries. At 100% and 150% DPI, confirm long definitions and result lines wrap without overlapping switches or controls and all five pages remain scrollable. Open exit, clear-logs, and every admin dialog; confirm the dimmed backdrop blocks the underlying UI, labels and buttons remain contained, Escape and backdrop clicks cancel safely, and destructive actions require their explicit button. Confirm install, update, and fatal-error choices use modern Windows Task Dialogs; runtime warnings use non-blocking Windows notifications, respect the notification preference, and remain deduplicated while the warning is unchanged. Confirm both left- and right-clicking the tray icon open its menu without raising the window; then confirm Open StageSwap opens the dashboard, Settings opens the Settings view, and the synchronized tray controls remain functional. Confirm the persisted missing-source fallback still behaves correctly; it no longer has a Settings editor.
12. In Windows Camera and Zoom, verify virtual-camera enumeration and preferred RGB32 1280×720 output at 30 fps. Confirm NV12 720p remains selectable and renders correctly when explicitly negotiated.
13. Stop automation and verify that the dashboard output and virtual-camera consumer both show the same black frame with the centered StageSwap app icon. Terminate the tray application and verify that the consumer continues showing that off frame. Repeat switching without functional failure.
14. In a release build, measure at least 300 post-warm-up frames for Force Webcam, Force Screen, Automatic, and a reversed transition. Require monotonic sample timestamps, at least 29 fps average wall-clock delivery, and no capture gap over 100 ms. Leave each of Windows Camera and Zoom running for several minutes and confirm the displayed rate remains 30 fps.
15. Enable and disable the optional webcam crop and confirm the same centered crop feeds both the preview and virtual-camera output. Verify a native 16:9 input is byte-identical with cropping enabled, a non-16:9 native input is centered and fills the output, and missing native-aspect metadata passes through unchanged.
16. Record Task Manager CPU for 60 seconds with the dashboard open and with the app hidden in the tray. Confirm runtime-owned FPS remains populated while hidden. Compare CPU with the previous build; it must improve materially, but there is no fixed percentage gate.
17. Install StageSwap beside Automatic Screen Camera. Confirm both cameras enumerate independently, neither can be selected as StageSwap's physical input, and StageSwap cleanup leaves the other product's files, data, registry state, startup value, and camera registration unchanged.
18. In Settings, verify primary clicks and a single secondary click on the logo do not open admin configuration, then double-click with the secondary button and confirm the hidden Admin configuration window opens. With no saved admin config, confirm only **Save current configuration** and **Back** are shown. Save an admin config with a reference image and confirm auto-restore appears disabled, then confirm the saved state shows **Save current configuration**, **Load saved configuration**, **Delete saved configuration**, and **Back** as full-width controls without clipping at 100% and 150% DPI. Change the session settings and reference, choose **Load saved configuration**, cancel once to verify the working setup stays unchanged, then confirm the action and verify the saved settings and reference are immediately applied and persisted while the Admin configuration page remains open. Enable auto-restore, change settings and the reference, relaunch manually and through Windows startup, and verify both are replaced by the admin config. Disable auto-restore and verify later session changes survive relaunch. Replace the admin config and confirm the toggle state is preserved; delete it and confirm auto-restore disappears while the working setup stays unchanged. Confirm **Back**, Escape, and backdrop clicks are non-destructive. Corrupt a copied admin profile in a disposable test directory and verify StageSwap keeps the working setup and displays a warning.
19. In Settings, click the Diagnostics tab five times with the primary button in under 3 seconds and confirm the mirrored disco ball lowers into the animated interface while the final virtual-camera output is decorated. No textual mode indicator should appear. The first click may navigate to Diagnostics and counts toward the sequence. Verify four clicks, a sequence longer than 3 seconds, clicks on another settings tab, clicks on either StageSwap logo, and mixed primary/secondary sequences do nothing. Confirm a secondary double-click on the Settings logo still opens only the admin configuration. Exercise Webcam, Display, Automatic, a reversed transition, tray-hidden operation, Stop, and Start: the effect must follow the final output, continue while hidden, leave the stopped StageSwap off frame unchanged, and resume after Start. Toggle it off with the same five-click gesture and confirm the ordinary UI and zero-copy steady output return. Relaunch and confirm disco starts disabled. In a release build, measure at least 300 post-warm-up disco frames and require at least 29 fps average wall-clock delivery with no gap over 100 ms; validate the result in Windows Camera and Zoom.

Run one smoke pass on physical x64 Windows hardware: launch, webcam capture, monitor capture, automatic switching, Windows Camera, Zoom, and manual restart. Add a display to the HDMI splitter while screen capture is running, reproduce the black feed, and verify two scheduled recovery checks restart capture and restore the image while manual Rescan remains discovery-only.

Before the manual pass, run the ignored interactive test set on the native target:

```powershell
cargo test -p stageswap-media-source --target <native-target> -- --test-threads=1
cargo test -p stageswap-windows --target <native-target> -- --ignored --test-threads=1
cargo test -p stageswap --target <native-target> -- --ignored --test-threads=1
```

These commands exercise COM activation and source/stream state, 300 screen frames with cursor on/off, stop invalidation, repeated physical-webcam start/stop, virtual-camera restart, all four runtime restart actions, and interactive tray creation. Run the UI visual comparison against the retained C++ screenshots at both 100% and 150% DPI.

Explicitly exclude webcam unplug/replug, continuous device rediscovery, general docking/display-reordering/resolution-change recovery beyond the confirmed black-screen restart above, vendor-driver compatibility, camera contention, sleep/resume, GPU recovery, and performance claims beyond the 1280×720-at-30-fps checks above. Those cases may fail until the user relaunches the application or selects the source again.
